# Another Language

Two separate things get translated, and mixing them up is the reason
admin i18n usually goes badly:

- **Kumi's own words** — `New`, `Search…`, `No access.`, `Verdict: ready`.
  These ship with Kumi, in the locales Kumi has strings for.
- **your words** — what your resources, attributes, workflows, stages and
  metrics are called. These are yours. Kumi has never seen them and
  cannot translate them; you write them.

The first is a locale. The second is a label.

## Set the locale

```elixir
app do
  name :pinto
  title "Pinto"
  locale :ja
end
```

That's the whole switch. The admin's chrome, `mix kumi.plan`'s prose and
`mix kumi.report`'s verdict all follow it. Available locales are
`Kumi.Locale.locales/0` — currently `:en` (the default) and `:ja`. An
unknown locale fails at compile time rather than quietly rendering
English.

For a one-off run in a different language than the app declares:

```bash
mix kumi.plan --locale ja
mix kumi.report --locale ja
```

## Name your own things

```elixir
admin do
  navigation [MyApp.Core.Account, MyApp.Core.Stamp]

  labels %{
    MyApp.Core.Account => "アカウント",
    {MyApp.Core.Account, :inserted_at} => "登録日",
    {MyApp.Core.Account, :stamps} => "スタンプ",
    :onboarding => "オンボーディング",
    {:onboarding, :invited} => "招待済み",
    {:overview, :account_count} => "アカウント数"
  }
end
```

A plain key labels a whole term — a resource module, a workflow name, a
dashboard name. A `{scope, key}` tuple labels something inside one: an
attribute or relationship of a resource, a stage of a workflow, a metric
of a dashboard.

The strings are free-form display text in whatever language you want.
They are not translation keys, there is no lookup behind them, and they
are used exactly as written — no pluralization pass, because appending
`s` is an English habit and you already wrote the form you meant.

Anything you don't list keeps the derived name (`Accounts`,
`Inserted at`). Anything you do list is checked at compile time: a label
for a resource this app never declared, or for an attribute that doesn't
exist, is a compile error rather than a line that silently never matches.

## Different wording, same language

To change one of Kumi's own strings without changing language, pass it in
the router. Only the keys you give are replaced:

```elixir
kumi_admin "/admin",
  app: MyApp.App,
  on_mount: [{MyAppWeb.LiveUserAuth, :current_user}],
  strings: %{ja: %{new: "登録", save: "確定"}}
```

The key names are the ones in `KumiAdmin.Locale.table/0`.

## What is deliberately not translated

- **Operation lines in `mix kumi.plan`.** `+ column apple_user_id text
  not null` is table names, column names and Postgres types. Rendering
  `column` as `列` would make the line harder to match against the
  database, not easier to read.
- **`SAFE` / `REVIEW` / `DANGEROUS`.** These are the classification's
  names — the same tokens `Kumi.Plan.Safety` returns as atoms and the
  guides document. They are identifiers, not sentences.
- **SQL.** A fix hint's prose is translated; the statement inside it is
  meant to be copied into psql.
- **`--json`.** `mix kumi.report --json` is always English. A consumer
  parsing it must not have values change language because someone set
  `locale :ja`.
- **Validation errors from Ash.** Form field errors come from Ash and
  AshPhoenix, not from Kumi, so they follow whatever those libraries do.
- **`:select` option values.** A `field :status, :select, options:
  [:lead, :won]` still renders `Lead` and `Won`. Labelling individual
  option values would be a third labelling surface; it isn't there yet.

## Adding a locale

`KumiAdmin.Locale` and `Kumi.Plan.Locale` are plain maps of whole
phrases. A phrase with a variable keeps the variable inside it —
`"%{name} 一覧へ戻る"`, never `"Back to " <> label` — because Japanese
puts the noun before the verb and the particle after the noun, and no
amount of care in translating the fragment fixes a sentence assembled in
English word order.

Each table has a test asserting that every `:en` key exists in every
other locale with the same bindings, so an untranslated string shows up
as a failing test rather than as a half-English page.
